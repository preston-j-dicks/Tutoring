What's on This Page

This portal has three sections stacked vertically:

  1. ML Analysis App — the analysis tool runs directly in the browser above. You can use it here or click Launch Analysis App to open it full-screen.
  2. Research Resources — your Google Drive folder is embedded below the app. Use it to access reference materials, papers, and your raw data files. Click Open Google Drive for the full Drive view.
  3. Instructions — this accordion. Expand any section to read guidance on the app, the ML pipeline, or how to deploy your own copy.

  • Open Google Drive — opens the shared folder where your data files and resources live.

Bookmark this page. It's your single hub for everything related to the organizational commitment study.

Work through the tabs left-to-right — they follow the logical order of a research analysis.

Tab 1 — Home / Resources

Welcome screen with links to this portal and the Google Drive. Start here to orient yourself.

Tab 2 — Data

Load data in one of two ways:

  • Synthetic dataset — click Load Synthetic Data to use a pre-built N=300 dataset with realistic correlations. Good for testing and understanding how the app works before you add your real data.
  • Upload your own file — drag-and-drop or browse for an Excel (.xlsx) or CSV file. After upload, the app shows detected columns.

After loading, you'll see checkboxes and dropdowns to:

  • Feature columns — check every column that is an input variable (gender, ideology, etc.).
  • Target column — select the column you're predicting (commitment: Stay/Leave).
  • Categorical features — check which features are categorical (names/labels, not numbers).

Click Confirm Column Setup when done.

Tab 3 — Preprocessing

Control how raw data is cleaned before training:

  • Imputation — how to fill missing values: median (default, good for skewed data), mean, or most frequent.
  • Scaling — normalizes numeric features: standard (z-score, default), minmax (0–1 range), robust (handles outliers), or none.
  • Feature Selection — automatically removes low-information features: none (keep all), variance (drop near-constant), or kbest (keep top K by chi-squared).
  • Class Balancing — if Stay/Leave counts are very unequal, use class_weight to compensate.
For most survey data, defaults (median / standard / none / none) work well. Change these only if you notice a model performing poorly or your class counts are very imbalanced.

Tab 4 — Model Config & Train

Each model has its own accordion panel with hyperparameter sliders:

  • Logistic Regression — C controls regularization strength; lower = simpler model.
  • Random Forest — n_estimators (number of trees), max_depth (complexity), min_samples_split.
  • Gradient Boosting — n_estimators, max_depth, learning_rate (step size).
  • SVM — C (margin penalty).
  • MLP (neural net) — layer sizes, dropout, learning rate, max epochs.

Auto-Tune — select a model and click Auto-Tune Selected Model to run automated hyperparameter search (Bayesian optimization). It updates the sliders with the best found values.

Click Train All Models to train all five with your current settings. Training takes 20–60 seconds depending on dataset size.

Tab 5 — Performance

Side-by-side comparison of all trained models: Accuracy, F1-score, ROC-AUC, and a confusion matrix per model. F1 is the primary metric — it balances precision and recall, which matters when Stay/Leave counts differ.

Tab 6 — Explainability

Four sub-tabs for understanding why the models predict what they predict:

  • PFI — Permutation Feature Importance: shuffles each feature and measures how much model performance drops. Higher bar = more important. Works for all 5 models. Select a model and click Compute.
  • SHAP — another model-agnostic importance measure. The bar height = average impact on prediction probability. Use this to corroborate PFI findings.
  • LRP — Layerwise-Relevance Propagation (neural-net only): traces which inputs the MLP relied on, layer by layer. You can view the average across the test set or inspect a single data row.
  • LogReg Coefficients — direct log-odds weights from Logistic Regression. Positive = pushes toward Stay; negative = pushes toward Leave. These are the most directly citable numbers for a paper.
For publication, report PFI + LogReg coefficients together. PFI is model-agnostic evidence; coefficients give directional effect sizes.

Tab 7 — Equations & Rationale

All mathematical formulas used in the app — loss functions, PFI definition, LRP propagation rules — rendered with full citations. Use this section to write the Methods section of your paper.

Tab 8 — Code Assistant

Requires an Anthropic API key (see setup below). Lets you read any source file and ask Claude to modify it in natural language. For example: "Change the MLP to have 3 hidden layers" or "Add a ROC curve to the performance plot."

Tab 9 — Decision Log

A timestamped record of every action the app took: what data was loaded, what encoding was used, what hyperparameters were set, what CV scores each model achieved. Click Export Log to download as a .txt file — paste it directly into your paper's supplementary materials as an audit trail.

If you want to run this app under your own HuggingFace account (with your own API key and full control), follow these steps.

Step 1 — Create a HuggingFace Account

Go to huggingface.co/join and sign up for a free account. Your username will appear in your Space URL.

Step 2 — Create a New Space

  1. Log in, click your profile icon → New Space.
  2. Name it (e.g., commitment-analysis).
  3. Set SDK: Gradio, visibility: Public (or Private).
  4. Click Create Space. HuggingFace creates an empty repo.

Step 3 — Get the Source Code

Download or clone the app source from the FissionLab deployment:

git clone https://huggingface.co/spaces/Dr-P/amy-commitment-analysis cd amy-commitment-analysis

Or download the ZIP from the Files tab on the Space page.

Step 4 — Push to Your Space

# Add your Space as a remote (replace YOUR_USERNAME and YOUR_SPACE_NAME) git remote add mine https://huggingface.co/spaces/YOUR_USERNAME/YOUR_SPACE_NAME # Push all files git push mine main

HuggingFace will automatically build and deploy. The build takes ~3 minutes.

Step 5 — Add Your Anthropic API Key (for Code Assistant)

  1. In your Space, go to Settings → Repository secrets.
  2. Click New secret.
  3. Name: ANTHROPIC_API_KEY   Value: your key from console.anthropic.com
  4. Save. The Space will restart with the key available — no code changes needed.
Never put your API key directly in a file. The HF Secrets system injects it as an environment variable securely.

Step 6 — Get an Anthropic API Key (if you don't have one)

  1. Go to console.anthropic.com and create a free account.
  2. Navigate to API Keys → Create Key.
  3. Copy the key (it starts with sk-ant-). Store it safely — you can't view it again.
  4. Free tier gives enough credits to use the Code Assistant for dozens of modifications.

Step 7 — Verify Your Deployment

  • Your app will be live at: https://YOUR_USERNAME-YOUR_SPACE_NAME.hf.space
  • Open it, load the synthetic data, train all models — confirm everything works.
  • Upload your own Excel/CSV file and confirm columns are detected correctly.
  • Go to Tab 8 (Code Assistant) and test a small change to confirm the API key is working.

Supported File Formats

  • Excel — .xlsx or .xls. Export from SPSS, Qualtrics, or Google Sheets.
  • CSV — comma-separated values. Any survey export tool produces this.

Preparing Your Survey Data

  1. Make sure column names are in the first row (headers).
  2. Each row = one respondent. Remove aggregate/total rows.
  3. The target column (commitment: stay/leave) should be binary — either 0/1 or text labels like Stay/Leave. The app encodes text labels automatically.
  4. Missing values are OK — the preprocessing pipeline handles them. Just don't drop rows manually unless the missingness itself is informative.

Column Mapping Tips

  • After upload, check every feature box that is an independent variable.
  • Un-check ID columns, timestamps, or free-text responses — these will confuse the models.
  • If your ideology scale is 1–5 or 1–10 instead of 1–7, it still works — the app treats it as numeric automatically.
  • Check the categorical box for any column that uses labels/names, even if stored as numbers (e.g., ethnicity coded as 1–5).

Exporting Results for Publication

  • Figures — right-click any chart and save as PNG, or use the Plotly toolbar (camera icon) for high-resolution export.
  • Decision Log — export from Tab 9 as .txt and include as supplementary material.
  • Coefficients — the LogReg sub-tab in Explainability gives direction + magnitude per feature; these go directly into a table in your results section.
  • PFI values — bar heights are mean F1 decrease. Report the top 3–5 features with their 95% confidence intervals (shown as error bars).
